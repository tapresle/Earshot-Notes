# Earshot Notes

Earshot Notes is a local-first meeting notes app. It transcribes your microphone and system audio on the device with Cactus Whistle, gives you a notepad during the meeting, and on request summarizes your notes and the transcript with a local LLM. It makes no network calls at runtime.

**Naming:** the app is "Earshot Notes", always in full in anything the app shows, including permission prompts and error messages. Docs may shorten it to "Earshot" after the first mention. The bundle identifier stays `com.tedpresley.earshot`, because the app data folder, the log folder, and macOS privacy permissions are keyed by it; changing it would hide existing meetings and models and ask for permissions again. Crate, binary, and package names stay `earshot`. The repository is `tapresle/Earshot-Notes`; its name affects only links, not the app.

macOS (Apple Silicon) is the first target. Windows and Linux follow.

## Stack

- **Shell:** Tauri 2. The Rust core lives in `src-tauri/`.
- **UI:** React 19, TypeScript, and Vite in `src/`.
- **Transcription:** Cactus Whistle through the prebuilt needle engine. `src-tauri/crates/needle-sys` holds the raw FFI, and `src-tauri/src/transcribe/whistle.rs` is the safe wrapper. Whisper large-v3-turbo through whisper.cpp is an optional download (#25): `src-tauri/crates/whisper-sys` loads it, `src-tauri/src/transcribe/whisper.rs` is the safe wrapper, and `src-tauri/src/models/transcription.rs` manages the choice.
- **Summaries and chat:** the local AI model runs through llama.cpp, embedded with `llama-cpp-2` and Metal, in `src-tauri/src/llm/`. Prompts are rendered with each model's own chat template through `minijinja`. Summaries are in `src-tauri/src/summarize/`, and chat in `src-tauri/src/chat/`. Model files are managed in `src-tauri/src/models/`.
- **Storage:** SQLite through `rusqlite`, in `src-tauri/src/store/`. The database lives in the app data directory as `earshot.db`.

The decision records in `docs/decisions/` explain why each piece was chosen.

**Screenshots after every UI change:** whenever a change can alter what the app draws, run `npm run screenshots` and commit the updated images in the same change. That includes components, CSS, UI text, the preview scenes in `src/preview/`, and updates to Playwright, which bring a new Chromium, even in a Dependabot pull request. Render them on macOS 27, the version CI checks them on (see **Continuous integration**), so text edges match exactly. Run `npm run screenshots:check` before you start, as part of your baseline, so a mismatch already on `main` isn't mistaken for yours.

## Continuous integration

GitHub Actions runs these checks on pull requests to `main` and on pushes to `main`:

| Workflow | Runner | Jobs |
| --- | --- | --- |
| `.github/workflows/ci.yml` | `ubuntu-latest` | Frontend lint, typecheck, and tests; `./scripts/generate-notices.sh --check` |
| `.github/workflows/screenshots.yml` | `xcode-27` (macOS 27, Apple Silicon) | `npm run screenshots:check`; on failure, uploads the rendered screenshots and their differences as the `screenshots` artifact |
| `.github/workflows/rust.yml` | `macos-26` (Apple Silicon) | `./scripts/fetch-native.sh`, then `cargo fmt --check`, clippy, and `cargo test --workspace` (summary tests on the CPU, see **Summary tests**) |

The screenshots workflow runs on macOS because the UI uses the system font, and only when the UI, the preview, the screenshots, or the npm dependencies change. It runs on macOS 27, the version the committed screenshots are rendered on, so text edges match exactly instead of within the tolerance. GitHub names that image `xcode-27` (there is no `macos-27` label), and it's in public preview; when it becomes generally available or a newer macOS replaces it, move the label and regenerate the screenshots on the new version together. The Rust workflow needs macOS 26 on Apple Silicon, because the prebuilt needle engine supports nothing else. It takes several minutes, so it runs only when `src-tauri/`, `scripts/fetch-native.sh`, `scripts/build-whisper.sh`, or the workflow itself changes. It caches the fetched native files and the whisper.cpp library (keyed on `fetch-native.sh`, `build-whisper.sh`, and the whisper.cpp interface in `src-tauri/crates/whisper-sys/native/`; checksums are still verified) and the cargo build (keyed on the repository name, the Rust version, and `Cargo.lock`; the build records absolute paths, which include the checkout folder named after the repository). A newer run on the same pull request cancels the older one. To rerun a failed job, use **Re-run failed jobs** on the run's page, or `gh run rerun <run id> --failed`. Workflows keep `permissions: contents: read` and pin each action to a full commit SHA, with its version in a comment.

Two more jobs keep the pins current (see **Updating pinned versions**). `.github/workflows/upstream.yml` runs `scripts/upstream/check.ts` every Monday, or from **Run workflow** on its page, and keeps one open issue, "Upstream updates available", current; it also has `issues: write`, for that issue only. Dependabot (`.github/dependabot.yml`) checks weekly and opens one grouped pull request each for Cargo, npm, and GitHub Actions minor and patch updates, and a separate pull request for each major update. The exception is `minijinja` and `minijinja-contrib`, whose major updates arrive together in one pull request, because neither compiles with the other's previous major version.

## Conventions

- **UI features** live under `src/features/<feature>/`. Each feature keeps its components, hooks, and tests together.
- **Rust modules** under `src-tauri/src/`: `audio` (microphone and system capture, downmix, resampling), `chunker` (speech segmentation), `transcribe` (Whistle, Whisper, and their worker thread), `recording` (start, stop, and the capture-to-worker pipeline), `llm` (the local AI model: the `Generator` trait, the llama.cpp generator, chat templates, keeping the model loaded, and `ModelWorker`, the thread that runs one summary or chat question at a time), `summarize` (summary prompts, condensing, titles, and the summary job), `chat` (answering questions about a meeting: notes passages, scoring sources, the prompt, and citations), `models` (known models, download, and GGUF import), `export` (Markdown rendering and file writing), `tray` (the menu bar icon and its menu), `window` (showing and hiding the main window and the Dock icon), `updates` (checking GitHub for a newer release), `vocabulary` (terms, mishearings, and correcting text with them), `store`, and `commands`. Tauri command handlers in `commands` stay thin and call into the other modules. Synchronous commands run on the main thread, so a command that touches the database, the disk, or another thread is `async` and does that work through `commands::blocking`, which moves it to the blocking thread pool. `Store` serializes access to its one connection with a mutex, and shared state such as `Store`, `Recorder`, and `ModelWorker` is managed as an `Arc` so the work can take its own handle.
- **UI and core communication:** the UI calls Tauri commands for requests, and the core pushes live updates as Tauri events. Current events: `transcript:segment`, `transcript:removed`, `recording:changed`, `recording:issue`, `summary:progress`, `summary:text`, `summary:done`, `summary:failed`, `chat:progress`, `chat:text`, `chat:done`, `chat:failed`, `model:download-progress`, `model:download-done`, `model:download-failed`, `transcription:download-progress`, `transcription:download-done`, and `transcription:download-failed`.
- **Menu bar and window:** Earshot Notes runs in the menu bar (`tray.rs`). Closing the window hides it and the Dock icon instead of quitting (`window.rs`), so recordings continue. Show and hide the Dock icon only through `macos_audio::show_dock_icon` and `hide_dock_icon`, never Tauri's `set_activation_policy`: the shim hides the app first and drops the Dock icon once it's inactive, and waits a second after a show, because otherwise macOS redraws the whole menu bar and every menu bar icon jumps; **Quit** in the menu bar or the app menu exits, and `RunEvent::Exit` stops any recording first. The window starts hidden (`visible: false` in `tauri.conf.json`) and setup shows it, unless macOS opened the app at login. Start and stop every recording through `commands::recording::start` and `stop`, never `recording::start_recording` directly: they emit `recording:changed` and update the menu bar, which is how the window learns about recordings started or stopped from the menu bar. The one exception is `RunEvent::Exit` in `lib.rs`, which calls `recording::stop_recording` directly: the app is exiting, so nothing listens for the event. Opening at login is macOS's own setting (`SMAppService`), read each time rather than stored in `settings`, and works only for the bundled app.
- **Audio pipeline:** capture threads must never block. They drop buffers when the pipeline falls behind. Captures send `audio::Buffer`, which carries the rate its samples were captured at, because a device's rate can change mid-recording (a Bluetooth headset drops to 16 or 24 kHz when its microphone opens). System audio follows the default output device: `audio/system.rs` watches it through `macos_audio::OutputDeviceWatcher` and rebuilds the tap on the new device, sending silence for the time between the two taps' buffers so transcript times stay in step; a failed rebuild reports a `recording:issue`. Never assume the rate from `CaptureFormat` stays fixed: `recording::run_pipeline` flushes the old resampler with `To16k::finish` and creates a new one when the rate changes, which keeps transcript times exact. Whistle receives 16 kHz mono segments of at most 28 s from `chunker`, which ends a segment after a 2 s pause and keeps 500 ms of it: people pause mid-sentence, and Whistle transcribes whole sentences far better than pieces (#99). Once a segment passes 20 s, a 160 ms pause ends it (`LONG_SEGMENT_FRAMES` and `LONG_SEGMENT_SILENCE_FRAMES`), so long speech splits at a breath instead of being cut at 28 s. Lines therefore appear about 2 s after the speaker stops. System audio uses a lower absolute speech floor than the microphone (`SYSTEM_MIN_SPEECH_RMS` and `MIC_MIN_SPEECH_RMS` in `chunker.rs`), because call audio is quieter and has no microphone hiss. Those are the **Normal** floors: each source has a stored `chunker::Sensitivity` (Low, Normal, or High) that `start_recording` reads and passes to `run_pipeline` through `Pipeline::new`. Transcript times are offsets from `meetings.started_at`. When the **Keep audio recordings** setting is on, `src-tauri/src/recordings.rs` saves each source's 16 kHz stream, before `chunker`, to `<app data>/recordings/<meeting id>/<offset>-<source>.wav` from a writer thread; the pipeline only hands samples over without waiting, and audio that doesn't fit is written as silence so the file keeps its timing. These files are full conversations: never log, export, or upload them. Whistle can invent short phrases such as "Thank you." from clips with little speech, and reports no confidence, so `chunker` measures each segment's speech time and loudness margin (`chunker::Speech`) and `transcribe/phantom.rs` drops a listed phrase only when its clip was weak. The **Vocabulary** setting (`src-tauri/src/vocabulary.rs`) works at three stages: a recording passes its terms to needle's keyword biasing with every job (read at start, like speech sensitivity; Whisper has no keyword biasing); `Store::insert_transcribed_segment` replaces listed mishearings, as whole words in any case, when a segment is saved; and the summary prompts list the terms to spell. **Add software terms** adds the preset in `src/features/settings/softwareTerms.ts` to the draft list as ordinary terms, with no mishearings (#104); measure any change to that list on real and non-software speech, because one keyword can garble an unrelated sentence. A corrected segment keeps what Whistle heard in `transcript_segments.heard_text`, which is NULL for segments no correction changed. Saving the vocabulary reapplies it to every stored segment from `heard_text` in one transaction, writing only rows that change, so removing a mishearing restores the original. Save transcribed segments only through `insert_transcribed_segment` (`store/transcribed.rs`), which reads the vocabulary under the same lock and drops echo: without headphones, participants' words come back through the microphone as "Me". `transcribe/echo.rs` compares text, not audio: a "Me" segment of three or more words is an echo when at least 70% of its words appear, in order, in what participants said within two seconds. Each source closes segments on its own pauses, so either can be saved first: an echo arriving after its source isn't saved, and a participant segment removes earlier "Me" echoes, which reach the window as `transcript:removed` (`{ meetingId, ids }`). A "Me" segment that mixes your words with echo keeps your words: `echo::without_echo` drops runs of four or more words that repeat what participants said. Stripping starts from what Whistle heard (`heard_text` when set) and reapplies the vocabulary, so both columns stay consistent. An earlier segment that loses echo is sent again as `transcript:segment` under its ID, and the window replaces it.
- **Packaging:** [`docs/building.md`](docs/building.md) has the build, signing, and notarizing steps for people; keep it in step with this paragraph. `scripts/build-macos.sh` signs with `APPLE_SIGNING_IDENTITY`, else the first Developer ID Application certificate in the keychain, else the first Apple Development certificate, else ad-hoc. With a Developer ID identity and notarization credentials (an App Store Connect API key or an Apple ID, described at the top of the script), Tauri notarizes and staples the app, and the script signs, notarizes, and staples the disk image, then fails unless Gatekeeper accepts the app, the disk image, and the app inside it. Credentials come from the environment, never from the repository. Without them, the build is signed but not notarized, and the script says so. The build uses the hardened runtime, so `src-tauri/Entitlements.plist` must keep `com.apple.security.device.audio-input`, or microphone input is silently denied. The deployment target is macOS 26 for every build, set in `src-tauri/.cargo/config.toml`; keep it equal to `minimumSystemVersion` in `tauri.conf.json` and `DEPLOYMENT_TARGET` in `scripts/build-whisper.sh`. After changing it, run `cargo clean` in `src-tauri/`: llama.cpp's build script doesn't notice the change, and a stale build fails to link with an undefined `__isPlatformVersionAtLeast`. Bundled license texts live in `src-tauri/resources/licenses/`. `third-party-notices.txt` there is generated by `scripts/generate-notices.sh` from the normal Rust dependencies for `aarch64-apple-darwin` (cargo-about, configured in `scripts/notices/about.toml`) and the production npm dependencies in `package-lock.json`; never edit it by hand. A dependency under a license missing from `accepted` in `about.toml` fails the script, so review the license before adding it there. An npm package published without a license file needs one in `scripts/notices/npm-fallback/<package>/`. `build-macos.sh` runs the script with `--check` and stops if the file is out of date.
- **Native macOS code:** `src-tauri/crates/macos-audio` holds the Objective-C system audio tap, the microphone permission calls, and the login item (`SMAppService`) calls, compiled by its `build.rs` with `cc` under `-Wall -Wextra -Werror`. Keep its C interface in `native/audio_tap.h` and its Rust bindings in `src/lib.rs` in sync.
- **Permissions:** the bundled app declares `NSMicrophoneUsageDescription` and `NSAudioCaptureUsageDescription` in `src-tauri/Info.plist`, and requires macOS 26, the oldest version the prebuilt needle engine supports. System audio permission is read and requested through the private TCC framework, loaded with `dlopen` so its absence degrades to "unknown" instead of a crash; keep that fallback when changing it. Under `npm run tauri dev`, macOS attributes both permissions to your terminal app instead.
- **Migrations:** schema changes are numbered SQL files in `src-tauri/migrations/`, applied in order through `PRAGMA user_version`. Never edit a shipped migration; add a new one and register it in `src-tauri/src/store/migrations.rs`.
- **Meeting list and search:** `list_meetings` returns one page at a time, keyed on `(created_at, id)` with a cursor rather than an offset, and takes an optional search query. Search uses external-content FTS5 indexes over `meetings.title`, `notes.body_markdown`, and `transcript_segments.text` (`src-tauri/migrations/0005_meeting_search.sql`, `src-tauri/src/store/search.rs`). Triggers keep them in step, so a migration that renames or rebuilds one of those tables or columns must recreate its index and triggers too.
- **Frontend data access:** call commands only through `src/lib/api.ts`. Tests mock `@tauri-apps/api/core` with an in-memory fake backend (see `src/App.test.tsx`).
- **Settings:** stored as key/value rows in the `settings` table through `Store::setting` and `Store::set_setting` (`src-tauri/src/store/settings.rs`). The selected local AI model (`selected_model_id`, through `store/models.rs`), how long it stays loaded (`keep_model_loaded`), whether first-run setup is done (`setup_complete`, through `commands/setup.rs`), the transcription model, the chosen microphone, each source's speech sensitivity, the vocabulary (as JSON), whether recordings keep their audio, and whether **New meeting** starts recording (`record_new_meetings`) live there. A missing microphone falls back to the system default and reports a `recording:issue`.
- **Markdown storage:** notes and summaries are stored as Markdown.
- **Export format:** each file has YAML front matter (title, local date with offset, duration), then `# Title`, `## Summary`, `## My notes`, `## Chat`, and `## Transcript`, in that order; an empty section gets a placeholder line, such as `_No chat._`. Headings inside the summary, notes, and answers are moved down one level. Chat citations are written as transcript times, such as `[00:12:05]`, or `[My notes]`. Folder exports never overwrite existing files; they add a numeric suffix. Times use the system time zone through `jiff`.
- **Offline only:** the app must not make network requests at runtime. The CSP in `src-tauri/tauri.conf.json` enforces this for the UI. There are two exceptions, both started by the user. The model download in `src-tauri/src/models/download.rs` fetches only entries from the pinned registry in `src-tauri/src/models/mod.rs`, summary models and `WHISPER_TURBO` (the UI passes a model ID, never a URL), and verifies size and SHA-256 before use. **Check for updates** in `src-tauri/src/updates.rs` asks GitHub's API for the latest release of `tapresle/Earshot-Notes` when you press the button, never on its own; **Open download page** opens a URL built from the release's version, never one from the response. Both run in Rust, so the webview's CSP doesn't change. Don't add other network calls. The README's **Private by design** section promises these rules to users; update it in the same change when they change.
- **Logging:** Rust code logs with the `log` macros (`log::error!`, `log::warn!`, `log::info!`, `log::debug!`), never `eprintln!`. `tauri-plugin-log`, set up in `src-tauri/src/lib.rs`, writes to stderr and to `~/Library/Logs/com.tedpresley.earshot/Earshot Notes.log` (named after `productName`), keeping one file of at most 1 MB. Logs stay on the device: don't add network or webview targets, and don't log transcript, notes, or summary text.
- **Network test:** `cargo test --lib -- --ignored resumes_from_hugging_face` checks a real ranged download from Hugging Face. It's ignored by default because it needs the network.
- **Styling** uses the CSS custom properties in `src/styles.css`. Every color needs a dark mode value.
- **Screenshots:** `docs/screenshots/` holds a light and a dark screenshot of each scene in `src/preview/scenes.ts`, so a pull request that changes the UI shows the change in its diff. They're generated, and committed on purpose, like `third-party-notices.txt`. `preview.html` renders the real `App` with `mockIPC` answered by the fake backend in `src/testing/fakeBackend.ts`, which `App.test.tsx` also uses; `vite build` bundles only `index.html`, so neither ships. `screenshots/scenes.spec.ts` opens each scene with Playwright at the app's default window size, a fixed clock, time zone, and locale, so unchanged UI renders identical images. Macs on different macOS versions draw text edges slightly differently, so the check tolerates a few pixels of edge shading per image (`playwright.config.ts` records the measurements); it still fails on a changed word, layout, or clearly visible color, but a very subtle change, such as a slightly different shade, can pass. Native control drawing changes even between builds of the same macOS (a select's arrow moved by two pixels between 27.0 and 27.0.1), so `screenshots/screenshot.css`, applied only while Playwright takes screenshots (`stylePath`), draws selects as plain boxes without the arrow. When a new control's native drawing makes the check fail on one Mac but not another, add it there rather than raising the tolerance. `npm run screenshots` rewrites only images that differ beyond that tolerance. To add a scene, add it to `scenes.ts` and a test to `scenes.spec.ts`, then run `npm run screenshots`. Scenes use synthetic data only.
- **Summary tests:** `src-tauri/tests/summarize.rs` runs a tiny real model (SmolLM2 135M, fetched by `scripts/fetch-native.sh`) to test plumbing such as streaming, limits, and cancellation, not summary quality. Logic above the model is tested through the `Generator` trait with fakes. Set `EARSHOT_TEST_CPU=1` to run that model on the CPU (`llm::llama::Placement::Cpu`); CI does, because the hosted runner's virtual GPU makes these tests take minutes. The app always uses the GPU. Summary quality is measured, not tested: `src-tauri/examples/summary_eval.rs` runs the app's summary code with a real model over the synthetic meetings in `src-tauri/tests/fixtures/meetings/`, which plant specifics such as ticket numbers, error messages, corrected values, and conditional plans, and reports which survive. `--noisy` makes transcripts look like real speech recognition output, `--pad MINUTES` spreads them across a long meeting, `--terms` passes vocabulary terms, `--context` forces condensing, and `--sampling` compares settings. For a condensed meeting, it also counts the specifics left after condensing (`found_in_parts`), which shows whether condensing or the final pass lost them; `SHOW_PARTS=1` prints the condensed parts. Put model files for it in `src-tauri/tests/models/`, which git ignores. Run it before and after any change to the prompts in `summarize/prompt.rs` or to sampling, and record the results in the pull request. `npm run benchmark` (`scripts/benchmark/run.ts`) runs it for each model at three meeting lengths, each run in its own process, and measures peak memory as the maximum resident set size, which counts the memory-mapped weights; macOS's peak memory footprint doesn't. Results and their write-up go in `docs/benchmarks/`, and every model must stay within the 10 GB budget described there.
- **Website:** earshotnotes.com is the static page in `site/` (#45): plain HTML and CSS, no build step, no framework, and no scripts, fonts, or requests to other domains. `netlify.toml` publishes `site/` on Netlify and sets the Content Security Policy that enforces this. Its copy follows the README; keep claims in step with the app, and keep the version in the page current with each release. `site/images/` is generated by `scripts/site-images.sh`; don't edit those files by hand.
- **Model lifecycle:** `ModelWorker` (`llm/worker.rs`) runs one job at a time, a summary (`summarize::job`) or a chat question (`chat::job`), on its own thread and keeps the model in an `llm::resident::Resident` between jobs. The model loads on the first job, not at app start, and stays loaded for the `keep_model_loaded` setting's idle time (`KeepLoaded`: **Never**, **5 minutes** by default, **15 minutes**, or **Always**); the idle time starts over after each job and when the setting changes. A job for a different model frees the loaded one before loading, so two models never take memory at once. Each job copies the meeting's notes, transcript, and vocabulary when it's queued, so edits made while it runs apply to the next job; the window asks `active_summary` and `active_chat` which meeting is busy. Each `generate` call creates a fresh llama.cpp context sized to its prompt plus its output room, so short meetings use less memory than long ones. Selecting a model saves the choice before calling `ModelWorker::unload`, so the next job loads the new model; removing a model also calls `ModelWorker::unload`, and quitting calls `ModelWorker::shutdown`, which cancels a running summary and frees the model: ggml's Metal backend aborts the process at exit while a model is loaded.
- **Chat:** the **Chat** tab (`src/features/chat/`) asks questions about one meeting (#24), answered by `chat::answer` with the local AI model, on `ModelWorker`'s thread and queue: a question asked while a summary runs is refused with a message that says which is running (`WorkerError::Busy(Work)`), and the reverse. Answers come from the meeting's own transcript and **My notes**, never its summary. When the whole meeting fits the context it's sent whole; otherwise `chat::retrieve` scores every segment and notes passage (`chat::passages`: paragraphs, list items, and headings) against the question in memory, keeps the best within the budget, and adds the segment on either side of each match. When nothing matches, the answer is `chat::prompt::NOT_COVERED` without calling the model. The prompt labels transcript lines `S1`, `S2`, and notes passages `N1`, `N2`, and answers cite them in brackets, such as `[S2, N1]`; `chat::citations` keeps only labels that were sent and saves what each one points to as `store::Citation`. The UI renders citations as buttons that scroll the transcript panel to the segment (`showSegment`, by element id, or the nearest start time once a segment is gone) or open **My notes** with the passage selected. A question and its answer are saved together in `chat_messages` when the answer finishes; a cancelled or failed question is not saved and goes back into the question box. The last few questions and answers, without citations, go with each new question, within an eighth of the context. Transcript and notes text is untrusted: the prompt tells the model to treat it as data, and chat has no tools or actions.
- **Rendering model output:** never render model output as HTML. Use `src/features/summary/Markdown.tsx`; its optional `citation` prop renders chat citation groups.
- **The note-taker in summaries:** notes call the note-taker "you". The transcript labels their lines "Me", and models copy it as a name, so `summarize/note_taker.rs` rewrites "Me" (and the owner tag "(me)") in the model's output, streamed and final. Telling the model to write "you" instead made it credit participants' tasks to the note-taker (#100).
- **Test data:** tests use synthetic audio and text fixtures only, with invented names; never names from real meetings, such as vendors, customers, or products. Generate speech fixtures with macOS `say`, for example `say -o tests/fixtures/name.wav --data-format=LEI16@16000 "text"`.
- **Native binaries:** `libneedle.a`, `.cact` model files, and the whisper.cpp build aren't committed. `scripts/fetch-native.sh` pins their Hugging Face revisions and SHA-256 checksums, then runs `scripts/build-whisper.sh`, which builds whisper.cpp from source at a pinned tag and commit. To change a version, update the pins and checksums there.
- **needle engine:** the engine holds one process-global, non-thread-safe model, so only one `Whistle` can exist at a time and it must stay on a single owner thread. `Whistle::transcribe` always passes English (`LANGUAGE` in `whistle.rs`): per-clip language detection read short or quiet call audio as other languages.
- **whisper.cpp:** whisper.cpp and llama.cpp each include ggml, and llama.cpp's copy is linked into the app, so whisper.cpp can't be linked in too. `scripts/build-whisper.sh` builds it, with the C interface in `src-tauri/crates/whisper-sys/native/earshot_whisper.{h,c}`, into `libearshot_whisper.dylib`, which exports only the `earshot_whisper_*` functions. Change the interface in the header, the C file, the export list in the script, and `whisper-sys/src/lib.rs` together. The app bundles the library in `Contents/Frameworks` (`bundle.macOS.frameworks` in `tauri.conf.json`), and `whisper-sys` opens it with `dlopen` on first use, so a missing library affects only Whisper; debug builds also look in `src-tauri/vendor/whisper/`. Each `transcribe::worker::Job` names its `Engine`. When Whisper is chosen, it loads when the app starts (`TranscriptionWorker::preload` in `lib.rs`) and stays loaded, like Whistle; choosing it in **Settings** loads it, and choosing Whistle or removing Whisper frees it. A recording's start preloads too, which retries a model that failed to load. The worker runs a job on Whistle when its Whisper model won't load; `job.engine` then reports Whistle. The `transcription_model` setting holds the choice, and `commands::recording::start` reads it with `models::transcription::selected_engine` when a recording starts, like the vocabulary; a deleted Whisper file falls back to Whistle. Whisper large-v3-turbo is `models::WHISPER_TURBO`, pinned like the summary models but kept out of `KNOWN_MODELS`; it has no row in the `models` table and counts as installed when its file is in the models folder, which only a verified download renames into place (`download::fetch_verified`). `models::manager::Downloads` runs one download of any kind at a time. **Settings** > **Transcription** (`src/features/settings/TranscriptionSection.tsx`) lists both models. The descriptions follow "What each model offers" in `docs/benchmarks/20261009-transcription-models.md`; keep the app, the README, and the website in step with it. Whisper gets no keywords. `transcribe/whisper.rs` strips the sound labels Whisper writes, such as `[BLANK_AUDIO]`, and the phantom filter applies to both engines. ggml's Metal backend aborts the process at exit while a model is loaded, so quitting calls `TranscriptionWorker::shutdown` after stopping the recording; tests that load Whisper through the worker call it too. `src-tauri/tests/whisper.rs` runs the tiny English model (`ggml-tiny.en-q5_1.bin`, fetched for tests only) and honors `EARSHOT_TEST_CPU=1`.
- **Git and pull requests:** don't add AI attribution anywhere: no `Co-Authored-By` or session trailers in commits, no "Generated with" footers or session links in pull requests, and no AI names in branch names. Commit as the repository owner. Name branches by purpose, such as `feature/<issue>-<topic>`, `bugfix/<issue>-<topic>`, or `chore/<topic>`.

## Updating pinned versions

Earshot pins exact versions, and nothing moves a pin without a pull request:

- **needle and Whistle:** revisions and checksums in `scripts/fetch-native.sh`.
- **whisper.cpp:** the tag and commit in `scripts/build-whisper.sh`. The upstream workflow doesn't check it yet.
- **Local AI models and Whisper large-v3-turbo:** repository, revision, and SHA-256 in `src-tauri/src/models/mod.rs`. Each revision is the last commit that changed the pinned file, which its Hugging Face page shows, not the head of the repository. Find it with the `paths-info` API and `expand: true`, and name its short form in the `version` string.
- **llama.cpp:** `llama-cpp-2` pinned with `=` in `src-tauri/Cargo.toml`, matching `RUNTIME_VERSION`.
- **Everything else:** `Cargo.lock`, `package-lock.json`, and the action SHAs.

The upstream workflow reports the first three; it counts a Hugging Face pin as outdated only when the pinned file itself changed, so README edits don't show up. Dependabot covers the rest and skips `llama-cpp-2` and `llama-cpp-sys-2`. A release takes an update when:

- **It fixes a security problem:** in the next release.
- **llama.cpp:** a model you want needs it, or it fixes a problem Earshot has. Run the summary tests and the summary benchmark (`npm run benchmark`) on the new version, then update `RUNTIME_VERSION` and each model's `min_runtime` with the pin.
- **needle and Whistle:** it improves accuracy or speed. Run the transcription tests and listen through recordings kept with **Keep audio recordings**. Move them together: each Whistle version has to match its engine.
- **A summary model's file changed:** compare the new file with the old one in the summary benchmark (`npm run benchmark`) before moving the pin. Earlier releases are unaffected: they download from the revision they pin and check its SHA-256.
- **Dependabot's grouped updates:** when CI passes. Read the changelogs of major version bumps first.

To decline an update, add it to `scripts/upstream/reviewed.json`, with the upstream file's SHA-256 or the crate version, a reason, and the date. The weekly check stops reporting that version and reports the next one. Record the measurements behind the decision in the tracking issue.

Every pin change gets a line in the next release notes.

## Releases

Each release has notes in `docs/releases/vX.Y.Z.md`. To make a release:

1. Set the version in `package.json`, `src-tauri/tauri.conf.json`, and `src-tauri/Cargo.toml`. They must match. Update the version shown in `site/index.html` too.
2. Run `./scripts/generate-notices.sh` to regenerate `src-tauri/resources/licenses/third-party-notices.txt`, and commit the result.
3. Write the release notes. The first release, `v0.1.0`, describes everything in the app. Later releases describe what changed since the previous one, grouped as new, improved, and fixed, and keep a known limitations section current. Use absolute links, such as `https://github.com/tapresle/Earshot-Notes/blob/main/LICENSE`, because the notes also become the GitHub release description, where relative links break.
4. Build with `scripts/build-macos.sh`, signed with Developer ID and with notarization credentials set, so it ends with "Notarized and stapled". Don't release a build that isn't notarized. The disk image is `src-tauri/target/release/bundle/dmg/Earshot Notes_X.Y.Z_aarch64.dmg`.
5. After the release branch is merged, tag the merge on `main` as `vX.Y.Z` with an annotated tag.
6. Push `main` and the tag to `origin`, then publish a GitHub release for the tag with the disk image attached. Use the release notes without their title line as the description, and add a **Download** section with the disk image's SHA-256. For example:

   ```bash
   gh release create vX.Y.Z <copy>/Earshot-Notes_X.Y.Z_aarch64.dmg --title "Earshot Notes X.Y.Z" --notes-file <notes> --verify-tag
   ```

   Upload a copy named `Earshot-Notes_X.Y.Z_aarch64.dmg`, not the build's own `Earshot Notes_X.Y.Z_aarch64.dmg`. GitHub replaces spaces in asset names with periods, and the hyphenated name keeps download links predictable.
